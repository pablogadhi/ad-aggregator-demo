# Component playbook

Recommended approach per technology, so components built on demand stay consistent. These are
starting points researched in Sept 2026 — **verify current versions and docs when building**
(context7 / official docs), and update the row with anything you learn.

| Component         | Status | Approach                                                                                                                                                                                                                        | Notes / gotchas                                                                                                                                                                                                                                                                                                                                                                                                                                    |
| ----------------- | ------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **postgres**      | built  | `cnpg/cloudnative-pg` 0.29.0 (operator 1.30.0) + `cnpg/cluster` 0.8.1 (release = instance, `fullnameOverride=<instance>`) + `bedag/raw` 2.0.2 glue `<instance>-glue` | ha = 3 instances, anti-affinity on zone. `-rw`/`-ro` services = primary/replicas. Sync replication is a values switch. The cluster chart has no `extraObjects`, so the glue release (installed **first**) renders `<instance>-app-credentials` (basic-auth → `cluster.initdb.secret.name`) and `apps/<instance>-conn` from one password: `lookup` of the existing secret, else `sha256sum` of the `data` Namespace UID + release. Chart gotchas: without `fullnameOverride` the Cluster is `<release>-cluster`; chart default `enableSuperuserAccess: true` (we set false) and a floating `postgresql:16` image (we pin `18.4-system-trixie`). `JDBC_URL` key for Flink/JVM clients. |
| **kafka**         | built  | Strimzi operator 1.2.0 (API `kafka.strimzi.io/v1`, Kafka 4.3.1, KRaft only), one `KafkaNodePool` of dual-role nodes + `Kafka` CR, all as `bedag/raw` 2.0.2 `resources:` (release `kafka-glue`, `values/<profile>.yaml` — **no separate chart deploys a Strimzi cluster**, so profile differences live directly in the glue values, not a cluster-chart `values/<profile>.yaml` + shared `glue.yaml` split); topics as `KafkaTopic` CRs; kafbat `kafka-ui` 1.6.5 (chart repo `https://ui.charts.kafbat.io/`, app v1.5.0) as its own release, `yamlApplicationConfig.kafka.clusters[].bootstrapServers` pointed at the bootstrap FQDN, `auth.type: disabled` | ha = 3 dual-role nodes, zone `topologySpreadConstraints` (DoNotSchedule) + `rack.topologyKey: topology.kubernetes.io/zone` (replicas in 3 zones, `RackAwareReplicaSelector`). Built-in `kafkaExporter` gives per-partition offsets / group lag; JMX rules from Strimzi's `kafka-metrics.yaml` (duplicated in both profile values files — bedag/raw's `resources:` list is replaced wholesale by a second `-f`, not merged, so it can't be factored into a shared file). v1 API: no `strimzi.io/node-pools`/`kraft` annotations, `metadataVersion` required-ish (pin `4.3-IV0`). `auto.create.topics.enable=false`. Kafka 4.x console tools: `--command-property`/`--reader-property` (old `--producer-property`/`--property` are deprecated). `kafka-configs --describe --all` prints each key twice (value + synonyms). kafka-ui's Service must be named `kafka-ui` (`fullnameOverride`) to match the `kafka-glue` HTTPRoute's `backendRef`. |
| **redis**         | built  | CloudPirates `redis` 0.35.4 (OCI `registry-1.docker.io/cloudpirates/redis`, app 8.10.2, official image digest-pinned), release = instance | `architecture: cluster`, 6 nodes / `clusterReplicaCount: 1`; the chart's post-install/upgrade Job forms the cluster (skips healthy, waits on recovering nodes). `cluster.announceHostnames: true` → `nodes.conf` holds FQDNs, so the cluster re-forms after all pods restart (replaces our old `start.sh`). `extraConfig` is appended last (AOF + `aof-load-corrupt-tail-max-size`, `protected-mode no` since auth is off). Conn secret via `extraObjects` (tpl-rendered). **Not zone-aware:** `--cluster create` may pair a primary with a same-zone replica — `smoke.sh` warns. Topology spread uses `matchLabelKeys: [app.kubernetes.io/instance]` (values can't template the release). Rejected: OT operator (Redis 7), Valkey operator (alpha). |
| **elasticsearch** | todo   | ECK operator (Elastic Cloud on Kubernetes, free Basic license), `Elasticsearch` + `Kibana` CRs                                                                                                                                  | Needs `vm.max_map_count>=262144` on the Docker VM (Docker Desktop: already 262144). small = 1 node, 1Gi heap; ha = 3 nodes with zone awareness (`node.attr.zone`). Default is TLS + auth: expose `URL` with https and the elastic user in the conn secret, or disable TLS on http for the lab.                                                                                                                                                     |
| **cassandra**     | todo   | cass-operator (K8ssandra), `CassandraDatacenter` CR                                                                                                                                                                             | Requires cert-manager (installed by the platform). One rack per zone. Cassandra is memory-hungry: small = 1 node 1Gi heap. Python driver: `cassandra-driver` (`LOCAL_DC` must match).                                                                                                                                                                                                                                                              |
| **flink**         | built  | Apache Flink Kubernetes Operator 1.16.1 (helm repo `archive.apache.org/dist/flink/flink-kubernetes-operator-<v>/` — downloads.apache.org drops old releases) + `bedag/raw` 2.0.2 glue `flink-glue` (PodMonitors, `flink-rest` Service, `flink-conn` — none of it a chart concern) | Watches `apps` (`watchNamespaces`), job SA `flink`. Jobs on **Flink 2.2.1** (`flink:2.2.1-scala_2.12-java17`, `flinkVersion: v2_2`): newest Flink with both Kafka (5.0.0-2.2) and JDBC (4.1.0-2.2, split into `-core` + `-postgres`) connector releases, though the operator already supports up to v2_4. Flink 2 keys: `execution.checkpointing.dir` (not `state.checkpoints.dir`). S3 on Floci works with `ENABLE_BUILT_IN_PLUGINS=flink-s3-fs-presto-2.2.1.jar` + `s3.endpoint`, `s3.path.style.access: "true"`. Operator default config adds a Prometheus reporter (9249) to every job; PodMonitor relabels a declared port to 9249 because Flink pods don't declare it. Autoscaler built in; `jobmanager.scheduler: adaptive` for in-place rescale. |
| **temporal**      | todo   | `temporalio/helm-charts` using CNPG Postgres for persistence (create `temporal` + `temporal_visibility` DBs via CNPG `Database` CRs). `lite` profile: single `temporalio/temporal` dev-server pod (`temporal server start-dev`) | UI at `temporal.localhost`. Workers are regular services (kind: worker) using the `temporalio` Python SDK with `TEMPORAL_ADDRESS`.                                                                                                                                                                                                                                                                                                                 |
| **aws**           | built  | quench community chart **`floci` 0.2.18** (OCI `ghcr.io/quenchworks/charts/floci`, Artifact Hub) — **Floci** 2.1.0 (MIT, no account, LocalStack-compatible port 4566) as Deployment + PVC; + `bedag/raw` 2.0.2 glue `aws-glue` for `aws-conn` (the chart has no `extraObjects`) | LocalStack needs an account + auth token since 2026.03 (free tier non-commercial); MinIO OSS is archived — avoid both. The chart already pins its hardened image **by digest** (`ghcr.io/quenchworks/images/floci@sha256:…`, human tag `"2.1.0"` matches — don't override `image:`). `floci.storage.mode: persistent` + `persistence.enabled: true`/`size: 5Gi` (the chart defaults to in-memory, ephemeral!); health at `/_floci/health` (not `/_localstack/health`). `fullnameOverride: aws` keeps the Service/endpoint identical to the old kustomize Deployment. Chart's `networkPolicy` defaults to same-namespace ingress only — set `allowExternal: true` since clients live in `apps`, Floci in `data`. Verified: S3 path-style put/get, multipart (ETag `-N`), SQS, Flink checkpoints via `flink-s3-fs-presto`. The `amazon/aws-cli` image has no `cmp` (use `md5sum`). Conn keys map 1:1 onto `AWS_*` env vars the SDKs read. |

## Real AWS (only when emulation isn't enough)

New accounts (since Jul 2025): $100 credit + up to $100 more; the _Free plan_ can't be billed and closes
after 6 months / when credits run out. Always-free: Lambda 1M req, SQS 1M req, SNS 1M publishes,
DynamoDB 25 GB (S3 is paid from credits). Add a Zero-Spend budget. Components never require it.
